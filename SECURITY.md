# Security Policy

## Supported Versions

The following versions currently receive security updates:

| Version | Supported |
| ------- | --------- |
| 1.x     | ✅ Yes    |
| < 1.0   | ❌ No     |

## Reporting a Vulnerability

Please report suspected vulnerabilities **privately**.

### Preferred Method

Use **GitHub Private Vulnerability Reporting** in this repository:
- Go to the repository
- Open the **Security** tab
- Click **Report a vulnerability**

### Alternative Method

If private reporting is not available, send details to:
- **security@your-domain.com**

### Please Do Not

- Do **not** open public GitHub issues for security reports.

### What to Include

To help us triage quickly, include:
- A clear description of the issue
- Steps to reproduce
- Affected endpoint(s), route(s), or component(s)
- Expected impact
- Proof of concept (if available)

### Response Timeline

We aim to provide:
- Initial acknowledgement within **48 hours**
- Triage decision within **5 business days**
- Progress updates at least **once per week** until resolution

### Disclosure Policy

- If accepted, we will work on a fix and coordinate disclosure timing with you.
- If declined, we will provide a brief explanation.
- We can credit you publicly for the report, unless you prefer to remain anonymous.

Thank you for helping keep the project secure.
